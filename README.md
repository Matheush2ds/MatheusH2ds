<h2 align="center">&#9679; como eu construo um back-end</h2>

<p align="center">
  <img src="./assets/architecture.svg" width="100%" alt="Diagrama animado: Client → API Gateway → Service Layer → Redis / PostgreSQL, com o response retornando ao client"/>
</p>

<div align="center">

|  | o que eu faço | por quê |
|:--:|:--|:--|
| **01** | Regra de negócio isolada de HTTP e ORM | trocar de framework ou de banco não deveria exigir reescrever o domínio |
| **02** | Timeout, retry com backoff e circuit breaker desde o começo | a chamada externa vai falhar; a questão é como o sistema reage |
| **03** | Log estruturado e métrica antes do deploy | sem isso, investigar produção vira chute |
| **04** | Estratégia de invalidação definida antes de escrever o cache | cache sem plano de invalidação vira bug silencioso |
| **05** | Unitário para lógica, integração nas bordas | é onde os erros realmente aparecem: banco, fila, API de terceiro |

</div>
